# Бот на GitHub Actions — пошагово

Бот запускается по расписанию каждые 10 минут, делает один проход и выходит.
Платить не нужно, карта не нужна.

**Минусы, с которыми жить:** запуск опаздывает на 5–20 минут; команды в Telegram
обрабатываются на следующем запуске; репозиторий должен быть **публичным**
(на приватном не хватит бесплатных минут).

---

## 0. Сначала остановите бота на этом компьютере

Иначе два процесса будут конфликтовать за `getUpdates` и часть команд потеряется:

```powershell
Unregister-ScheduledTask -TaskName GoldSignalBot -Confirm:$false
```

---

## 1. Создайте репозиторий

1. Зайдите на [github.com](https://github.com) → **New repository**.
2. Имя: `gold-signal-bot` (любое).
3. Видимость: **Public** (обязательно — иначе не хватит минут).
4. **Не** добавляйте README и .gitignore при создании.
5. Создайте.

## 2. Загрузите файлы

Самый простой путь — через браузер:

1. Распакуйте `gold-signal-bot-upload.zip` в папку.
2. На странице репозитория: **Add file → Upload files**.
3. Перетащите **содержимое** папки (не саму папку), включая `.github` и `deploy`.
4. Внизу: **Commit changes**.

Если папка `.github` не перетаскивается (некоторые браузеры её прячут):

1. **Add file → Create new file**.
2. В имени напишите: `.github/workflows/signals.yml` (слэши создадут папки).
3. Вставьте содержимое файла из архива.
4. **Commit changes**.

Проверьте, что в репозитории есть:
`bot.py`, `config.ci.json`, `requirements-bot.txt`, `.github/workflows/signals.yml`.

> `config.json` в репозиторий не кладём — он содержит токен. В CI он создаётся
> из `config.ci.json`, а токен берётся из секрета.

## 3. Добавьте токен как секрет

1. В репозитории: **Settings → Secrets and variables → Actions**.
2. **New repository secret**.
3. Name: `TELEGRAM_BOT_TOKEN`.
4. Value: ваш токен от @BotFather.
5. **Add secret**.

## 4. Первый запуск

1. Вкладка **Actions**.
2. Слева выберите workflow **signals**.
3. Кнопка **Run workflow** → **Run workflow**.
4. Откройте запуск и посмотрите лог шага «Один проход».

В логе должно быть:

```
INFO bot: Бот: @Kidzord_bot (Gold signal bot)
INFO bot: Инструменты: gold/1h[breakout,asian], ...
INFO bot: Один проход завершён: сигналов 0, закрытий 0
```

## 5. Подписка

Состояние на GitHub стартует пустым — подписчиков там пока нет.
Отправьте боту в Telegram `/start`. Это сообщение обработается **на следующем**
запуске (в течение ~10 минут), вы попадёте в подписчики, и состояние сохранится
в кэше Actions.

Проверить: через 15 минут отправьте `/status` — бот ответит на следующем запуске.

## 6. Дальше — само

Расписание `*/10 * * * *` работает автоматически. Каждый запуск:

1. восстанавливает `state.json` из кэша;
2. скачивает котировки, проверяет сделки и сигналы;
3. обрабатывает накопившиеся команды;
4. сохраняет состояние обратно в кэш.

---

## Ограничения, которые надо знать

| Ограничение | Что делать |
|---|---|
| Задержка запуска 5–20 минут | смириться или перейти на VPS/Raspberry |
| Команды не мгновенные | ответ придёт на следующем запуске |
| Репозиторий публичный | не кладите в него `config.json` и `state.json` |
| Через 60 дней без активности GitHub отключает расписание | раз в месяц зайдите и нажмите **Run workflow** |
| Кэш Actions может протухнуть (7 дней без использования) | при ежедневной работе не протухает; если пропустили месяц — снова `/start` |
| Одновременные запуски | защищены `concurrency`, второй ждёт первого |

## Если что-то не так

- **Красный крестик в Actions** → откройте лог, обычно это отсутствующий секрет
  (`TELEGRAM_BOT_TOKEN`) или токен с опечаткой.
- **Бот не отвечает на команды** → проверьте, что локальный бот остановлен,
  и что workflow на ветке `main` (расписание работает только с default branch).
- **Сигналы не приходят** → это нормально: их 2–4 в неделю по всем инструментам.
  Посмотрите `/status` — там время последней свечи по каждому инструменту.
- **Хочу быстрее** → замените `*/10` на `*/5` в `.github/workflows/signals.yml`
  (GitHub всё равно может задержать).

## Переход на VPS или Raspberry позже

Когда надоест задержка — инструкции рядом: [DEPLOY.md](DEPLOY.md),
[DEPLOY-PI.md](DEPLOY-PI.md). Достаточно остановить workflow (Actions → signals →
⋯ → Disable workflow), чтобы два бота не конфликтовали.
